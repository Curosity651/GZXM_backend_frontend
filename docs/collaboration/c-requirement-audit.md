较早的 `docs/development-plan.md` 还要求**自筹材料也能新增/删除自定义文件夹**，本分支目前只对国家材料实现了自定义文件夹；应作为未完成的原计划项，由团队确定是否仍在 C 当前交付范围。较早的 `docs/api/api-reference.md` 对国家文件夹仍写“只能本单位新增/删除”，与用户的新授权口径及 OpenAPI 现状不一致，需要在合并评审中统一。不能把这两处视为已完成。

B 的只读契约校验脚本 `docs/collaboration/b-contracts/validate.py` 把基线 API 操作数固定为 67。本分支为本地文件字节传输在 OpenAPI 增加两个 Files 操作，因此该脚本的总数断言需要由 B 在契约评审时更新；本分支没有修改 B 的测试或业务代码。这里是**协作检查点**，不能用本分支自己的 OpenAPI 解析通过来代替 B 的评审。

## 验证和不能宣称的范围

数据库业务逻辑并非空壳：报告和归档服务包含参数化 `SELECT/INSERT/UPDATE`，文件服务通过 `FileObjectMapper` 更新文件元数据；关键写操作使用 `@Transactional`，报告提交/审批有行锁、幂等键和快照，归档关联/删除锁文件夹行，自筹项目用 `record_version` 条件更新。数据库 ACID 与磁盘/NAS 文件不是同一个事务，上传失败后的 PENDING/孤儿对象和 NAS 掉线恢复仍需运维清理与对账；完整边界写在 `c-file-storage-temporary.md`。

单元/集成测试与实际后端 API 联调验证了报告字数例外、国家材料文件夹权限、上传关联与读取、自筹项目日期/状态更新、工作台。当前 `frontend/src/pages/LoginPage.tsx` 和 `AuthGuard.tsx` 仍使用演示 store；`VITE_API_MODE=real` 的 C 业务页面虽已编写，但真实登录/会话及整个前端路由没有接通，所以浏览器演示界面通过不等于真实 API 的前后端端到端通过。该接入涉及 A 负责的公共登录和会话边界，本分支未越界修改。

文件存储还有三项明确限制：对象/API 型 NAS 需要新的适配器与按历史 `storage_provider` 路由；挂载目录掉线检测目前只在启动时检查目录存在；上传采用 `byte[]` 且未清理长期 `PENDING`/孤儿对象。临时文档 `c-file-storage-temporary.md` 给出当前实现、环境配置、迁移步骤和这些边界。
