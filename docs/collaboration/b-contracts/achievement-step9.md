## 2. 实现内容

### 2.1 类型与客户端

- `frontend/src/api/research/contracts.ts`：从 OpenAPI 生成的 32 个 B 所需类型及引用类型，ID 保持字符串。
- `client.ts`：覆盖 B 的 24 个操作，消费 A 的单位查询；统一调用已有 apiRequest，不自行实现认证或刷新。
- 过滤参数保留 false/0，路径和查询值编码；课题选择器读取完整分页，不静默只取前 20 条。
- 动作/审批/下发发送 Idempotency-Key；同一页面内相同操作与请求体重试复用原键，改变请求体生成新键。不将 Token 或业务数据写入 Mock Store。
- 指标草稿使用专门的 MetadataRequest 对接入口；没有公共能力、头缺失或数值非法均拒绝，不能把空数组当成版本零。
- 类型与五类表单字段提供 `--check`，检测 OpenAPI 漂移。字段白名单、枚举和长度来自 OpenAPI，中文名称沿用现有 B 表单。

### 2.2 课题、成员、指标

- 原有 `/indicator`、`/indicator/topic/:topicId` 页面入口根据现有 `VITE_API_MODE` 选择真实/Mock 子组件，未改路由。
- 课题分页查询、编辑、状态与启停；更新携带读取到的 recordVersion，409 显示错误，要求重新读取，不自动覆盖。
- 新建时可同时指定成员；编辑不传成员数组，保持原关系；牵头单位单独添加、停用、恢复承担成员。
- 科研助理可维护课题；仅当前牵头且有对应权限的单位维护成员和分配，停用/暂停课题禁用写入口。
- 已下发指标与草稿明确区分；保存完整替换当前节点草稿，空列表清空；草稿未保存时不能下发。
- 草稿版本与发布版本分开显示，分配还保留绑定的课题发布版本；错误和冲突不伪装成功。

### 2.3 成果和审批

- 真实成果分页、课题/单位/状态筛选、待我审批列表；详情重新获取最新记录，展示审批历史、提交快照和材料关联版本。
- 五类详情表单；草稿不强制正式阶段字段；创建只允许本单位已下发的基础指标，包含零目标。
- 编辑锁定课题、节点和基础指标，发送最新读取的 recordVersion。仅改详情时省略 materialAttachments，不误清空既有材料。
- 提交预审、登记投稿/申请、开始正式草稿、正式/补充提交；服务端决定状态，前端不计算“成功后的假记录”。文件未就绪时明确显示依赖提示，并保留服务端拒绝。
- 初审/终审按钮同时要求固定角色、权限码和状态；退回必填意见；审批发送 submittedVersion 与 recordVersion。
- 操作期间阻止重复点击；失败保留表单和重试键；成功后重新读取服务器列表与统计。

### 2.4 统计

- 调用 `/achievement-progress`，不从 Mock 或页面当前分页推算总量。
- 节点筛选只控制累计统计；上方成果列表为所选课题/单位的分页记录，避免将累计与单节点过滤混为一谈。
- 展示五类基础生效数、当前成员指标、专项子集与单独的停用历史页签；历史不参与当前总量。
- 正确显示未下发、零目标和 null 完成率；保留两位小数，允许超过 100%；课题/单位/专项行不相加。

## 5. 本地验证

### 当前可以执行

1. 使用 Java 21 在 backend 执行 `.\mvnw.cmd test -B -ntp`。默认使用 Docker/Testcontainers；如使用本地 MySQL，必须是隔离的 `gzxm_topic_test_*` 库，测试会重置夹具，绝不能指向部署库。
2. 在 frontend 使用受支持的 Node 版本执行 `npm test`、`npm run lint`、`npm run build`。本次使用 Node 24；本机原生 lint 依赖处理沿用 [validation.md](validation.md)。
3. 运行已有各 `validate-*-responses.py` 及 `validate.py`；再运行：

```powershell
python docs/collaboration/b-contracts/generate-research-types.py --check
python docs/collaboration/b-contracts/generate-research-fields.py --check
```

Python 需要已有的 PyYAML/契约检查依赖，可沿用前八步临时验证环境。本次未向项目添加依赖。

4. 默认 Mock 模式仍展示原型。当前即使设 `VITE_API_MODE=real`，**也不能通过旧 Mock 登录页完成真实登录**；B 页面在没有真实会话时显示错误，不能把原型数据视为真实验收结果。不建议手工注入 Token 或篡改全局 Store 绕开待交付的公共登录流程。
5. 此前后端接口仍可通过 Postman 和本地真实测试账号验证，参考第 2—8 步说明。本步没有数据库升级要求。
