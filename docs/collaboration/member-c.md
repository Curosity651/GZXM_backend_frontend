# C：月季报、归档与工作台任务单

本地 C 分支的复核记录见 [需求与边界审查](c-requirement-audit.md)；当前磁盘文件服务的接口、配置、限制和 NAS 迁移路径见 [文件存储临时实现说明](c-file-storage-temporary.md)。两份文档描述未合并代码，供其他协作人员和模型核对。

## 主责范围

- `report`：每课题独立规则、月报/季报、初审、终审和进度。
- `archive`：单位独立国家材料、自筹项目、目录、文件关联和归档进度。
- `dashboard`：按当前用户权限聚合待办与进度。

## 对外契约

- 使用 A 的认证、权限和审计。按本次协作约定，文件服务由 C 自行实现；归档模块只调用 C 文件服务的公开接口。
- 使用 B 的课题成员与牵头单位公开查询，不访问课题 Mapper。
- 归档材料不建立审批状态或审批记录。

## 首批任务

1. 实现每课题独立月季报规则和仅牵头单位提交约束，不为未填月份生成报告。
2. 实现月季报初审、终审及版本快照。
3. 实现每课题每单位独立国家材料清单与自定义目录。
4. 实现内部单位自筹项目；外部单位在接口和查询层均拒绝访问。
5. 实现归档进度和工作台聚合，并覆盖越权读取测试。

## 文件存储与未来 NAS

- 当前 `FileStorage` 的文件系统实现把字节写在 `FILE_MOCK_ROOT` 指定的目录（默认是后端工作目录下的 `storage/mock`）；数据库 `file_object` 只保存文件元数据、存储类型与相对 `object_key`，不保存字节，也不保存绝对路径。尽管旧类名仍为 `MockFileStorage`，它确实写入磁盘。
- 新环境可设置 `FILE_PROVIDER=FILESYSTEM`，并把 `FILE_MOCK_ROOT` 配为**已存在、可写的绝对路径**；应用在路径无效时拒绝启动，避免误写到相对工作目录。旧记录中的 `MOCK` 类型仍可由该实现读取。上传成功后，服务端再次验证存储内容的长度和可选 SHA-256 才把状态改为 `READY`。文件在同目录临时写入后重命名；不支持原子重命名的文件系统会退回普通重命名。
- 若 NAS 以 NFS/SMB 目录挂载，保持相同的相对 `object_key`，先复制并核对旧目录全部文件，再把 `FILE_MOCK_ROOT` 指向 NAS 挂载目录并重启服务。数据库及报告/归档 API 不需改变。切换前须检查挂载确实存在且可读写，避免 NAS 离线时误写本机同名目录；迁移期间暂停上传并保留旧目录备份，验证下载后再恢复。
- 如果选定的 NAS 仅提供对象存储/HTTP API 而非目录挂载，应新增 `FileStorage` 适配器，并让服务按记录的 `storage_provider` 选择读适配器。现阶段协议未知，不应把 NAS 地址写入数据库或业务模块。
- 单文件当前上限 100 MB，服务端会把文件读入内存进行校验。若未来有大文件或大量并发上传，再把文件接口改为流式传输；这不影响归档目录和数据库的业务模型。

## 待团队统一确认的表结构变更

- 国家材料自定义文件夹需要独立的“提交文件内容说明”字段；现有 `archive_folder` 没有适合持久化此说明的列，不复用“不适用原因”等不同业务含义的字段。确定长度与是否允许编辑后，新增迁移、读写接口和创建表单。
- 配套自筹项目负责人需要联系电话、单位名称和部门；现有 `self_funded_project` 仅有 `principal_name`。确定联系人与项目单位的字段归属、长度及历史数据补录规则后，新增迁移、必填校验和编辑表单。
- 当前文件夹保护规则根据创建者**现有**角色判断。若要求创建后即使创建者换岗也永久保持保护，需要在文件夹中保存创建时的角色快照，并通过新增迁移实现。
- 不修改已合并的迁移文件；上述变更应由团队评审后追加新迁移。当前已可使用现有 `required_flag` 保存“必存/有则必存”，`created_by` 约束删除权限，项目开始/结束日期及状态可更新，无需新增字段。
