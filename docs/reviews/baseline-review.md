# API与数据库基线评审记录

评审基线：2026-09-15。

## 已冻结内容

| 范围 | 结论 |
|---|---|
| API版本 | 使用`/api/v1`，共67个操作；OpenAPI 3.1为机器级唯一契约 |
| 身份认证 | 短期JWT访问令牌＋Redis单次轮换刷新令牌；刷新令牌使用HttpOnly Cookie |
| 权限顺序 | 账号、RBAC、内外部属性、课题成员、牵头关系、数据所属、业务状态 |
| 用户角色 | 创建时选择角色，编辑基本资料时不能修改角色；停用代替删除 |
| 密码重置 | 服务端生成随机临时密码，只返回一次，同时使已有令牌失效 |
| 数据库 | MySQL 8.4、InnoDB、utf8mb4，共27张基础表 |
| ID | 数据库使用BIGINT，API使用string，避免JavaScript精度问题 |
| 版本 | 可编辑记录使用`record_version`；提交审核使用递增的`submitted_version`和快照 |
| 软删除 | 账号、单位、文件夹和文件保留历史；审批和快照只追加不覆盖 |
| 文件 | 业务仅依赖文件服务，当前使用Mock适配器，后续可替换MinIO/S3 |
| 归档 | 国家材料和自筹材料均不审批，上传成功即参与完成度统计 |

## 三人签署要求

- A确认公共响应、认证、用户权限、文件和迁移基线。
- B确认课题、成员、指标和成果字段及状态。
- C确认月季报、国家材料、自筹材料和进度字段及状态。
- 进入B/C业务编码前，应在任务系统中记录三人的评审结果；后续破坏兼容性的变化必须另建契约任务。
